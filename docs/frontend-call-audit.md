## Frontend assumptions not provided by the backend

`connection_lost` and `call_cancelled` are locally synthesized frontend events, not backend WebSocket events (`frontend/src/lib/callSocket.js:13-17, 54-59`; `frontend/src/state/callReducer.js:23-34`). Development-only mock replay/scenarios (`frontend/src/App.jsx:57-65, 87-103`) and test-tone playback (`frontend/src/hooks/useCallSocket.js:221-227`) also do not represent backend capabilities. No goodbye-phrase end heuristic was found.

## Stage 3 verification: microphone and audio (2026-10-26)

This is a verification addendum; the original point-in-time audit above is unchanged. Existing implementation and tests were reviewed against `docs/ws-event-contract.md:22-28, 73-80, 110-113` and `docs/frontend-call-integration.md:50-64`.

| Area | Verified behavior and evidence | Outcome |
|---|---|---|
| Permission and mono capture | The user-start path requests permission only after the start action (`frontend/src/App.jsx:170-178`, `frontend/src/hooks/useCallSocket.js:95-102`); capture requests one channel (`frontend/src/lib/micLifecycle.js:51-59`) and the worklet forwards the first channel (`frontend/public/mic-worklet.js:1-5`). | **Verified compatible** |
| Input PCM, resampling, and frames | Capture resamples to 16 kHz and frames 320 samples (`frontend/src/hooks/useCallSocket.js:154-157, 183-186`); float samples are clamped/converted and framing writes signed PCM16 little-endian (`frontend/src/lib/pcmCapture.js:1-10, 40-58`). This is 20 ms per frame at 16 kHz. | **Verified compatible** with mono little-endian PCM16 at 16 kHz. |
| Send gate and backpressure | `frontend/src/lib/micLifecycle.js:4-27` sends only when live, socket-open, and buffered amount is at most 256 KiB; otherwise it drops the frame and records the rejection. | **Verified compatible**; no audio buffering is added while not live or under backpressure. |
| Output format and order | `frontend/src/lib/pcmPlayer.js:18-52` decodes little-endian PCM16 and creates mono buffers at 24 kHz; sequential `nextStartTime` schedules chunks in order. `frontend/src/lib/callSocket.js:28-32` routes binary frames to playback. | **Verified compatible** |
| Interruption and cleanup | `frontend/src/hooks/useCallSocket.js:121` flushes on the received `interrupted` event. `disposeAudio` (`useCallSocket.js:41-55`) and `cleanupMic` (`frontend/src/lib/micLifecycle.js:30-40`) stop tracks, disconnect capture nodes, close the audio context, and close the player (which flushes active playback, `frontend/src/lib/pcmPlayer.js:5-16, 54-58`). End calls and terminal connection/status paths invoke cleanup (`useCallSocket.js:125-133, 213-220`). | **Verified compatible** for hang-up, disconnect, terminal error, and interruption paths. |

Existing focused tests verified the paths without microphone hardware, real audio, or Gemini: `framer emits little-endian complete frames and holds remainder`, `48k resampling has expected length and preserves DC`, `44.1k resampling is stable over uneven chunks`, `16k resampling passes through identically`, `mic gate drops frames before live`, `mic gate sends frames while live and socket open`, `mic gate drops frames when socket is closed`, `mic gate drops frames above 256 KB backpressure`, `converts Int16 samples 0, 32767, and -32768 to Float32`, `carries an odd-length chunk byte across enqueue calls`, `schedules back-to-back chunks without a gap`, `flush stops every active source and resets scheduling`, `enqueue after flush schedules from currentTime`, and `close can be called twice safely`.

Verification on this date: `node --test` passed (85 tests); `npm run lint`, `npm run format:check`, and `npm run build` passed. No Stage 3 application or test changes were needed. Hardware/browser-device behavior and a real provider session were not exercised; no audio bytes were logged.

## Mic-gate regression follow-up (2026-10-26)

The live mic ref was previously overwritten on every incoming WebSocket event using a predicate that was false for non-status events. Since the backend emits `provider_activity` on its first provider event (`backend/app/main.py:151-152`), that event could switch off the microphone frame gate after `status: live`.

`useCallSocket` now updates the ref only through `updateMicLiveState` for status events; a live status enables sending, every non-live status disables it, and existing `disposeAudio` cleanup still explicitly resets the ref to false (`frontend/src/hooks/useCallSocket.js:41-43, 123-125`; `frontend/src/lib/micLifecycle.js:4-6`). The focused regression test proves `provider_activity`, `transcript`, and `tool_result` preserve live sending and `status: ending` rejects frames as `not_live` (`frontend/tests/micLifecycle.test.js:42-73`).

Verified: `node --test tests/micLifecycle.test.js` passed (11 tests); full `node --test` passed (87 tests); `npm run lint`, `npm run format:check`, and `npm run build` passed. No backend changes or Gemini calls were made.
